```markdown

> 状态：阻塞 | 部分完成 | 已完成

## 结论

一句话说明当前状态和交付结果。

## 前置检查

- 已读取的上游 handoff 及状态。
- 开工时 Git 状态和相关并发修改。

## 修改文件

- 按文件列出本路线修改及目的。

## 公共接口与行为

- 记录下游必须知道的签名、错误语义、时序和约束。

## 验证

| 命令 | 结果 | 备注 |
| --- | --- | --- |

## BUS 延后项

- 只能在总线执行的 build、tarball、E2E、lockfile 或跨包检查。

## 删除候选

- 旧文件、入口、fixture 及其替代证据。这里只登记，不提前删除。

## 风险与阻塞

- 未解决问题；没有则写“无”。

## 下游与总线动作

- 按 tasks 所有权表分别列出需要 D 汇聚的 core export、E 汇聚的 SDK export，以及 BUS 处理的 root
  manifest、lockfile、目录重命名、数据库或文档状态；不得把 D/E 前置动作一律延后给 BUS。
```

## 状态规则

- `阻塞`：不得被下游当作前置条件。
- `部分完成`：不得被下游当作前置条件。
- `已完成`：路线范围内实现和可安全执行的定向验证已完成，延后项已明确交给所有权表指定的 D、E 或 BUS。
